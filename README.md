# Итоговый проект, сервис TODO-LIST

## Описание проекта

Сервис TODO-LIST предназначен для создания списка задач. С его помощью можно удобно отслеживать задачи.

## Список выполненных заданий со звездочкой

1. Реализована возможность определять извне порт при запуске сервера. 
2. Реализована возможность определять путь к файлу базы данных через переменную окружения.
3. Реализованы правила со звёздочкой для функции NextDate. 
4. Реализована возможность выбора задачи через поле для поиска и выбора задачи на конкретную дату.
5. Реализован механизм аутентификации.
6. Создание Docker образа.

## Инструкция для запуска кода локально

1. Нужно создать файл .env в корне проекта, далее заполнить его по примеру файла .env.example, но уже со своими значениями:

```bash
TODO_PORT=определите_порт_для_сервера(7540)
TODO_DBFILE=определите_путь_к_файлу_базы_данных_например_(scheduler.db)
TODO_PASSWORD=придумайте_пароль_для_авторизации_на_сайте(111)
```

2. Сервис готов к запуску, используйте следующую команду:

```bash
go run main.go
```

3. После запуска перейдите по указанной ссылке в браузере, сменив порт на тот, который вы указали в .env:

```bash
http://localhost:порт_который_вы_указали/
```

## Инструкция по запуску тестов

Перед тем как запускать тесты, запустите сервер.

1. Тестирование запуска веб-сервера:

Если вы хотите использовать другой порт, замените его в файле .env.

```bash
go test -run ^TestApp$ ./tests
```

2. Тестирование базы данных:

По умолчанию тест считает, что файл с базой данных scheduler.db находится в родительской директории. Вы можете указать другой путь в значении переменной DBFile в файле ./tests/settings.go. Если переменная окружения TODO_DBFILE определена, то можете хранить путь к базе данных там.

```bash
go test -run ^TestDB$ ./tests
```

3. Тестирование функции NextDate() и обработчика /api/nextdate:

Так как все правила повторения реализованы, то переменной FullNextDate в файле ./tests/settings.go присвоено значение true.

```bash
go test -run ^TestNextDate$ ./tests
```

4. Тестирование добавления задачи:

```bash
go test -run ^TestAddTask$ ./tests
```

5. Тестирование поиска и получения ближайших задач:

Будьте внимательны, тест предварительно удалит все задачи из базы данных.

Тестирование поиска будет только в том случае, если в файле ./tests/settings.go переменной Search присвоено значение true.

```bash
go test -run ^TestTasks$ ./tests
```

6. Тестирование редактирования задачи:

```bash
go test -run ^TestTask$ ./tests

go test -run ^TestEditTask$ ./tests
```

7. Тестирование API /api/task/done (выполнение задачи):

```bash
go test -run ^TestDone$ ./tests
```

8. Тестирование удаления задач:

```bash
go test -run ^TestDelTask$ ./tests
```

9. Выполнение всех тестов:

Чтобы протестировать реализацию аутентификации, присвойте переменной Token в tests/settings.go значение токена, которое сервер возвратил из /api/signin и которое хранится в куке token.

Для запуска всех тестов используйте команду:

```bash
go test ./tests
```

## Инструкция по сборке и запуску проекта через Docker

Прежде чем запускать проект через Docker, запустите сервер локально для инициализации базы данных, в случае если она отсутствует.

Команды для сборки и запуска проекта через Docker:

```bash
docker build --tag ваше_название:v_ваша_версия .

docker run -p ваш_порт:порт_контейнера -v "$(pwd)/scheduler.db:/myapp/scheduler.db" ваше_название:v_ваша_версия
```
